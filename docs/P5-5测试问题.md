## P0-A · 配额归零【回归，本轮 P5-4 配额重算引入】
**现象**（组 5 / 组 4b）：删掉个别书后「已用」变 **0**，但账号里实际还有很多书。用户指出「上一个配额修改绝对有问题，之前的预扣式反而准」。
**根因（已代码确认）**：
- P5-4 第二轮把配额改成触发器重算 `bytes_used = SUM(file_size WHERE file_key IS NOT NULL AND deleted=false)`。
- 但 `collect_dirty` 推送元数据时 `file_size: 0`（[sync_engine.rs:42,409](../src-tauri/src/sync_engine.rs)），且 `BookUpsertRow.file_size` **不是** `skip_serializing_if`（只有 cover_key/file_key 加了）——所以**每次元数据 push（翻页 bump updated_at 即触发）都把云端 file_size 覆盖成 0**。
- file_size 一旦被抹 0，触发器 SUM 就 =0 → 配额归零。删书只是触发了一次重算、暴露了它。
- e2e 测试没抓到：`quota_accounting_five_scenarios` 上传后没再 push 元数据；旧预扣式不依赖 file_size 故无此症。
**修法方向**：别再让元数据 push 抹 file_size——把 `BookUpsertRow.file_size` 改 `Option<i64>` + `skip_serializing_if none`，`collect_dirty` 送 `None`，只有 `upload_book_file` 的 PATCH 写真实 file_size（和 file_key 一个套路）。改完补一个「上传后再 push 元数据、配额不变」的 e2e 场景。

## P0-B · 删/加churn 后跨端下载失败【严重，偶发】
**现象**（组 4c）：iPad 反复删/加书几轮后，其他端对个别书**下载失败持续 10 分钟**（排除上传耗时）。**登出再登录**后能下载，但**个别设备个别书丢封面**。
**初步假设（待查证）**：删除会签发预签名 DELETE 清 R2 对象；若书随后被复活（MA-7 revive）但云端行 file_key 仍指向已删对象、且尚未重传 → 另端下载 GET 报 404「文件未就绪」。登出/登录全量重来才自愈。丢封面同理（cover_key 与实际对象不一致）。
**待办**：需专门查删→复活→重传的时序/一致性（cloud_state/file_key/R2 对象三者），可能要「复活时清云端 file_key 或强制重传后再置就绪」。**优先级高但需先复现+查证，别急着改**。

## P1-A · 书库不随后台同步刷新【UX，影响面广】
**现象**：
- 组 1：登录后同步下来的书/封面**不显示**，切换排序才出来。用户判断：书库页在登录前已加载，登录不主动重刷。
- 组 4a：Mac/Windows **没有下拉刷新**，删的书一直留在页面，切排序才消失（iOS 有下拉刷新可手动）。
**根因**：后台同步引擎改了本地库（新增/删除书、下载到封面）后，**前端书库视图不会响应式重刷**。`library-changed` 事件目前只在切账号时发（MA-6），常规同步变更不发。
**修法方向**：同步引擎在「合并拉取有实际变更 / 下载完封面 / 应用了墓碑删除」后 emit 一个事件（如 `library-changed` 或新事件），前端 Library 监听→reload。桌面端也顺带补一个手动刷新入口（可选）。这样组 1、组 4a 一并解决。

## P1-B · 已下载的书被打回「云端」重新下载【CONFIRMED】
**现象**（组 2）：进度同步后，同一本书在其他设备**从「本地」变回「云端」**，点开又重新下载。
**根因（已代码确认）**：`merge_remote_books` 的 UPDATE 无条件 `cloud_state='remote'`（[sync_engine.rs:193](../src-tauri/src/sync_engine.rs)）。另一端 push 了进度/元数据（bump updated_at）→ 本端 pull→merge UPDATE→把本已 `synced`（文件在本机）的书打回 `remote` → 显示云端、点击重下（内容寻址同路径覆盖，无重复文件但白下一次）。
**修法方向**：merge 更新时**不要把本地已有文件的书降级为 remote**——若本地 file_path 对应文件存在（或当前是 synced/local），保持其状态；只有本机确无文件时才置 remote。

## P2 · 断网操作卡死转轮【UX】
**现象**（组 6）：飞行模式下点下载 / 下拉刷新→转轮**一直转**，**重新联网也不恢复**，约 **3 分钟**后才冒系统性错误。
**根因**：3 分钟 ≈ 阻塞请求/命令超时（下载命令 180s 或 reqwest 默认超时叠加）。离线没有快速失败、UI 无超时兜底、在飞行中发出的请求联网后也不取消/重试。
**修法方向**：① 请求加较短的连接超时、离线快速失败并给明确文案；② 前端转轮加超时兜底（到点停转+提示）；③ 联网后允许重试/自动追平不被旧卡住的请求阻塞。
